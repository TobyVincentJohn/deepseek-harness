# Agent Note: Code Mode 操作指南与碎片化运行提醒

Status: implemented

[English](2026-08-22-code-mode-operational-guidance.md) | 中文

## 问题

Code Mode SDK 虽然要求模型批处理确定性工作，但遗漏了决定批处理能否成功的操作事实。模型可能依赖 `require`、把 worker 进程目录误认为会话工作区、遗漏嵌套工具的必填参数、在只读任务中创建中间文件，或把一次归档分析拆成许多不同的 `run_code` 程序。精确参数重复 guard 无法识别最后一种模式，因为每段程序文本都不同，而且外层调用之间还会出现嵌套分发。

## 决策

TypeScript SDK 与 `run_code` schema 要求模型通过已声明的工具绑定完成任务 I/O，避免使用 Node 模块与 `process` API，通过嵌套工具解析相对工作区的路径，并传入嵌套工具的所有必填参数。两种语言的 SDK 都要求只读任务避开变更类工具和创建文件的命令，并要求归档或日志分析流式处理输入、输出紧凑汇总，不得为每个文件或子问题分配一个外层程序。Bash 定义进一步强调使用单个多行脚本或流水线，并遵守只读限制。

`repeat-tool-reminder` 接受 `countByTool`，其中的通配工具名模式使匹配的根调用忽略参数、按工具名计数。嵌套分发对该根调用链透明；另一条受跟踪的根调用会重置它。这类序列收到不含参数的合并提醒，而 `countByTool` 之外的工具仍按规范参数精确匹配。包默认值为空，基础 bundle 配置为 `[run_code]`。

提醒仍只提供建议。它不会阻止调用，也不会施加通用运行次数上限；worker 运行时的进程目录与 Node 能力保持不变。

## 验证

工具生成测试固定 TypeScript 与 Python SDK 说明、按语言区分的 `run_code` 描述以及 Bash 定义。Guard 测试会改变外层参数、在外层调用之间执行嵌套调用、覆盖两级提醒，并验证另一条受跟踪的根工具会重置序列。无密钥快照固定组装后的 Code Mode 提示词与传输 schema。

## 曾考虑的替代方案

**所有工具都忽略参数、只按名称计数。** 否决，因为针对不同目标的连续读取、搜索、编辑和轮询属于正常进展。忽略参数的计数需要显式的窄范围列表。

**把嵌套分发视为链重置。** 否决，因为每个有用的 Code Mode 程序都包含嵌套调用；该规则会使外层 `run_code` 序列在结构上不可见。

**达到固定程序数量后阻止调用。** 否决，因为探索性工作可能合理地需要多个程序，而且该 guard 的既定职责是提供建议。阈值提醒保留模型的决定权。

**在本次修复中改变 worker 的进程目录。** 暂缓，因为这会改变运行时语义而非模型指南，需要单独分析兼容性与隔离。嵌套工具已持有会话工作区解析约定。

## 后果

Code Mode 请求会携带额外的稳定提示词与 schema 文本。模型会在常见运行时错误和违反只读要求之前收到具体纠正；即使程序文本或嵌套工具发生变化，碎片化的 `run_code` 序列也会触发提醒。合理的长序列可能在配置阈值处收到提醒，但执行行为不变。
