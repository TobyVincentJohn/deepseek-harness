# Agent Note: 有界构建器执行

Status: implemented

[English](2026-08-22-bounded-builder-execution.md) | 中文

## 问题

合成任务生成将大部分工具时间花在重复发现确定性的机械步骤上。观察到的 DeepSeek 构建器运行中，一次最终任务包工作负载发出了 1,715 条命令，九个保留的架构会话产生了 669 次模型到工具往返。这些架构会话累计约 156 分钟用于生成模型输出，而执行根工具不足四分钟，同时追加了 29 个至少 40,000 字符的工具结果。通用 harness 在任务开始前还会暴露约 69,000 个字符、分布于 26 个工具的静态定义。这些成本掩盖任务推理、增大请求，并让失败的机械步骤在没有终止条件的情况下重复。

## 决定

harness 提供一条构建器专用执行路径，其中包含五项相互配合的控制：

1. `@deepseek-ai/dsh-tool-builder` 提供基于 `warcio` 的进程内 WARC 列表／搜索／读取工具 `corpus_query`，以及面向流水线冻结 SQLite FTS 索引的只读批量适配器 `architecture_corpus_query`。索引工具在每条目及完整结果限制下合并统计、多条搜索、精确最终／请求 URL 读取和可选列表。
2. 随附的 `builder` agent preset 只挂载文件系统编辑与搜索、Bash、后台任务、构建器工具及压缩。它省略无关的 Web、skill、workflow、plan、委托、自修改与代码运行时 schema。
3. `validate_builder_package` 一次执行共享的低成本最终任务包交接检查。`validate_architecture_candidate` 使用配置的路径和语料限制调用流水线自有校验器，在完整结果限制下返回其 JSON 报告，并保留校验器的报告与合并计划输出。harness 不复制流水线校验规则。
4. `dsh-repeat-tool-reminder` 可在达到配置的精确重复、按名称计数或连续失败预算后拒绝调用。基础组装允许四次已完成的相同根调用、80 次连续 `run_code` 或 `bash` 根调用，以及 12 次连续失败的根调用，随后拒绝下一次调用。新的用户输入会重置计数器。
5. `dsh-compaction-tool-result-pruner` 使用有效且带摘要的 JSON 替换历史中超大的工具调用参数，该 JSON 包含有界的头尾预览。完整原始事件保留在仅追加会话日志中，而替换会在模型可见表层保持工具名、调用 id 以及调用／结果配对。

构建器工具与 preset 的模型可见文本保持英文。该 preset 可供选择，但不会改变部署默认值。

## 所有权与限制

`corpus_query` 负责机械式归档检查，不负责浏览器渲染或语义检索。由于 `ctx.fs` seam 不提供原始字节流，它会通过该 seam 在可配置字节限制内缓冲压缩归档。`architecture_corpus_query` 只接受流水线记录的 FTS5 documents 表，以只读方式打开，且无法中断一条同步 SQLite 语句。`validate_builder_package` 只负责最终任务包交接共有的不变量检查；`validate_architecture_candidate` 将全部架构语义委托给配置的流水线脚本。签名清单、rubric 语义、Harbor、校验器执行与评分仍由流水线负责。

收敛预算按活跃 agent 隔离并仅驻留内存。它们基于语法证据运行：精确的规范参数、根工具名与失败结果。工具输入剪枝仅在压缩压力或规范溢出使剪枝阶段符合条件后发生。它会添加替换事件，而不是修改或删除源事件。

## 考虑过的替代方案

**继续生成 Python WARC 脚本。** 这种方式保留最大灵活性，但会反复承担脚本构造、语法错误、依赖发现与近似相同的归档扫描成本。维护中的 JavaScript WARC 解析器删除了这些重复机械步骤，同时让工具保持在文件系统 seam 内。

**使用通用 preset 执行构建器工作。** 单一 preset 更容易描述，但每次请求仍会携带与离线任务生成无关的 schema 和指令。可选择的窄 preset 保持通用表层不变，并明确构建器表层。

**只依赖提醒而不拒绝。** 建议性阈值能帮助有响应的模型，但无法为观察到的 107 次精确调用循环建立终止条件。可配置的分发前预算限制浪费，同时允许部署用零禁用强制限制。

**截断或覆盖原始工具事件。** 破坏性剪枝会使回放与精确审计不再符合实际运行。仅追加替换保留源证据，并为后续模型请求提供有界表层。

**从校验工具运行完整 verifier。** 这会把低成本生成检查与任务自带代码、容器、凭据及评分混合在一起。原生校验器刻意止步于共享的确定性交接。

**在 harness 中重新实现架构校验。** 复制大型流水线 schema 会让两个组件在架构规则演进时产生分歧。结构化适配器保持面向模型的调用稳定，同时让流水线继续独占校验语义和合并计划生成。

**为每条架构查询扫描所有索引文档。** 架构阶段已经生成 FTS5 索引和精确文本行。复用该索引可在一次调用中支持多条查询，并避免重复解析归档或让模型编写 Python。

## 后果

常见 WARC 发现、批量架构研究、架构校验和任务包检查变成有界原生调用，构建器也从明显更小的工具表层开始。精确循环、碎片化 shell／程序序列与不间断失败都有可配置的停止点。大型历史 heredoc 与生成脚本不再逐字出现在每次压力后的请求中，同时其哈希与原始事件保留身份与可审计性。

WARC 查询可能在内存中持有最多 `maxArchiveBytes` 的压缩数据，其 HTML 转换刻意保持简单，纯文本扫描也不是索引。低成本校验器无法确认任务质量。合理的长轮询或恢复可能触及硬预算，并需要新的用户输入或改变后的动作。参数变体可以绕过精确预算，因此选定的高风险工具还使用更广的按名称计数限制。

## 测试

包测试覆盖压缩 WARC 操作、归档中的 SQLite FTS schema 与精确读取契约、完整结果裁剪、结构化架构校验器调用、聚合任务包失败、硬预算路径、输入替换、摘要元数据、配对与回放稳定性。无密钥的 builder-preset 快照固定组装后的系统指导与精确工具名单。保留的构建器制品提供了这些测试采用的索引 schema、校验器 CLI 契约和工作负载证据。
